全局架构概览

Claude Code 是什么？它如何组织代码？核心组件有哪些？

🎯 一句话理解

Claude Code 不是一个新 AI 模型，而是一个编排层（Orchestration Layer）。它把 Claude 大模型（Opus / Sonnet / Haiku）包装起来，赋予它读写文件、执行命令、搜索代码、启动子代理等能力，通过一个简单的 while 循环不断调用工具，直到任务完成。

💡 核心洞察：Claude Code 没有意图分类器、没有任务路由器、没有 RAG 管道、没有 DAG 编排器。模型本身决定一切——何时调用工具、调用哪个工具、何时完成。这就是 Anthropic 所说的 "Less scaffolding, more model"（少搭脚手架，多信模型）。

核心循环 (Master Loop)

Claude Code 的心脏——一个简单却强大的 while 循环

📝 伪代码理解

// Claude Code 核心循环伪代码 async function agentLoop(userPrompt: string) { const messages = [buildSystemPrompt(), { role: "user", content: userPrompt }]; while (true) { // 1. 调用 Claude API (流式响应) const response = await streamClaudeAPI(messages); // 2. 检查是否完成 if (response.stop_reason === "end_turn") { return response.text; // 任务完成！ } // 3. 处理工具调用 for (const toolCall of response.tool_calls) { // 3.1 权限检查 if (!await checkPermission(toolCall)) { const approved = await askUser(toolCall); if (!approved) continue; } // 3.2 执行工具 const result = await executeTool(toolCall); // 3.3 追加结果到消息历史 messages.push({ role: "tool", content: result }); } // 4. 上下文管理（必要时压缩） if (getTokenCount(messages) > 150000) { messages = await compactContext(messages); } } }

📊 核心工具详解

工具 用途 关键行为 权限级别
Bash 执行 Shell 命令 万能适配器，可运行任何 CLI 工具 高危

TodoWrite 追踪任务进度 结构化任务管理 安全

全局配置 ~/.claude/CLAUDE.md

🔑 关键限制：子代理深度限制为 1（depth=1），即子代理不能再生成子代理。只有摘要结果会返回给主代理，不会污染主上下文。

⚙️ 7 种权限模式

模式行为适用场景风险
default 每次工具调用都询问用户 日常开发 低
auto-accept 自动批准所有工具调用 CI/CD 高

✅ Claude Code 优势

  • 超大上下文：200K tokens
  • 原生多文件：自动关联修改
  • Shell 集成：执行任何 CLI
  • 子代理隔离：并行不污染
  • 插件生态：MCP 协议

❌ Claude Code 局限

  • CLI 优先：上手门槛高
  • 仅在线：无离线模式
  • Anthropic 专属：不支持其他模型
  • 成本：Opus 调用较高

设计哲学

理解 Anthropic 的设计取舍

✅ Claude Code 选择

  • 简单 while 循环
  • 模型驱动决策
  • Grep 搜索，无 RAG
  • 子代理隔离上下文
  • 插件系统，MCP 协议

❌ Claude Code 不做

  • 意图分类器
  • DAG 工作流编排
  • 嵌入向量 / RAG
  • 本地模型运行
  • 图形化界面

🎯 核心设计原则

1

Less Scaffolding, More Model

少搭脚手架，多信模型。

2

Search, Don't Index

搜索而非索引。

3

Isolation by Default

默认隔离。

4

Progressive Enhancement

渐进增强。
